Web Search is a managed search API that returns URLs and metadata for any query. Use it from a Workers binding, the REST API, or any MCP client. No instances to create, no namespaces to configure.

Web Search is a discovery tool. It finds relevant URLs on the public web so your agents can decide which pages to read. To get the content of a page, pair Web Search with [Browser Run](/browser-run/) or the standard `fetch()` API.

## Use cases

- **AI agents that need real-time information**: give agents the ability to search the web as a tool call, then fetch and act on the results
- **Grounding LLM responses**: reduce hallucinations by searching for current information before generating a response
- **Multi-step research**: search across queries, fetch content from the best results with [Browser Run](/browser-run/), and synthesize across multiple sources
- **MCP tool for coding assistants**: use Web Search from Claude Code, Cursor, OpenCode, or any MCP client

## Web Search vs AI Search

Web Search and [AI Search](/ai-search/) are different products for different jobs:

- **Web Search** discovers URLs on the **public web**. You provide a query, it returns matching pages from across the internet.
- **AI Search** searches **your own data**. You index your content, and it provides managed retrieval over your documents.

Use Web Search when your agent needs real-time information from the open web. Use AI Search when you need search over content you control.
